# Лабораторная работа 3, вариант 9

Группа Б24-507, Демидович В.А., номер по списку 6.
Задача коммивояжёра на 12 вершинах, потоковая формулировка устранения подциклов.

## Установка

Проверено на Python 3.13.3. HiGHS входит в SciPy и отдельно не устанавливается.

```sh
python -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
```

В Windows для активации: `.venv\Scripts\activate`.

## Полный расчёт

```sh
python main.py
```

Запуск из папки работы. Пути к данным определяются относительно main.py, поэтому можно указать путь к скрипту и из другой папки. Программа последовательно решает LP-релаксацию и MILP трёх сценариев, сравнивает с жадной эвристикой, выполняет эксперимент с большим M и серию на 10, 20 и 40 вершинах. Лимит основного MILP — 30 секунд на задачу, серии — 8 секунд на размер. Фактическое полное время включает несколько запусков солвера и построение рисунков.

## Данные

- data/nodes.csv — координаты 12 точек, км.
- data/arcs.csv — стоимость каждой из 132 направленных дуг, условные денежные единицы.
- data/config.json — вариант, seed=10006, закрытые дороги и параметры запусков.
- generate_data.py — воспроизводимый генератор данных. Повторная генерация: `python generate_data.py`. Она перезаписывает только данные.

Координаты равномерно распределены на квадрате 100 × 100 км и округлены до сотых. Стоимость направленной дуги — евклидово расстояние, умноженное на случайный коэффициент от 1 до 1.25, с округлением до сотых. Тариф в обратную сторону может отличаться. Для сценариев используется фиксированная перестановка дуг с seed=10007: закрыты первые 26 или 52 дуги. Это примерно 20% и 40% исходных 132 дорог. Списки замыканий вложены друг в друга и не зависят от найденного решения.

## Разные значения gap

В сценариях интегральный зазор определён как 100·(Z_MILP−Z_LP)/Z_MILP; он характеризует слабость непрерывной релаксации и относится к доказанному оптимуму только при статусе optimal MILP. Зазор ветвления `mip_gap` — оценка солвера между найденным целочисленным решением и текущей нижней границей. Статус time limit не означает доказанную оптимальность; наличие допустимого маршрута отдельно проверяется.

## Дополнительная проверка

`python check_results.py` проверяет сохранённые планы, воспроизводимость данных и три оптимума независимым динамическим программированием Хелда — Карпа. Скрипт также проверяет, что дробный план, несколько отдельных циклов, отрицательные значения, закрытые дороги и неправильный искусственный поток отвергаются. Итоги сохраняются в results/validation_checks.json. Проверка генерации перезаписывает данные теми же значениями с фиксированным seed.
